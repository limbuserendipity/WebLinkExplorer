# Neon Air Hockey — тестовая motion-игра (Godot AR API v1)

Аэрохоккей на двоих в ретро-неоновом стиле: вид сверху, 2D. Слева в кадре —
игрок 1 (голубая ракетка), справа — игрок 2 (розовая). Цель — забить диск
в лунку соперника. Матч до 5 голов.

**Управление «головой».** В API v1 нет координат головы, поэтому игра
использует прокси: верхнюю центральную точку рамки силуэта
(`camera_rect_norm`).

| Движение головы | Ракетка |
|---|---|
| влево / вправо | вверх / вниз по столу |
| присед / выпрямление | назад / вперёд |

Нейтральное положение калибруется во время обратного отсчёта перед раундом —
стойте ровно, голова прямо. Жесты (`jump`/`lean`) в управлении не участвуют,
но сигнал `gesture` обрабатывается (вспышка кольца вокруг ракетки).

## Запуск

### С реальной системой трекинга

1. Откройте папку `neon_air_hockey/` в Godot 4.5.1, импортируйте проект
   (один раз — чтобы движок сгенерировал `.godot/`).
2. В системе трекинга: **Tab → Игры → Добавить игру → выбрать `godotar.json`**.
3. Игра стартует автоматически с аргументами `--port=N` (и при необходимости
   `--rotation-seconds=S`).

### Демо без трекинга

Просто запустите проект в Godot — включается демо-режим:

- игрок 1 — **WASD**, игрок 2 — **стрелки**;
- **Пробел** — старт матча / реванш.

### Эмулятор трекинга (без камеры)

Из корня проекта:

```bash
python3 tools/mock_tracker.py
```

Скрипт напечатает команду вида `godot --path . -- --port=PORT` — выполните её
в отдельном терминале. Эмулятор шлёт двух игроков, двигающих «головой» по
синусоиде, и периодические жесты `jump`.

Сценарии для приёмочных проверок (см. `--help` в скрипте):

```bash
python3 tools/mock_tracker.py --leave 12        # правый игрок уходит на 3 с и возвращается
python3 tools/mock_tracker.py --swap 12         # у правого меняется track_id при том же slot
python3 tools/mock_tracker.py --empty 12        # players пуст на 3 с
python3 tools/mock_tracker.py --stale 12        # поток молчит на 3 с (данные устаревают)
python3 tools/mock_tracker.py --drop 12         # соединение закрывается
python3 tools/mock_tracker.py --lowconf         # жесты с confidence 0.45 (ниже порога)
python3 tools/mock_tracker.py --video           # JPEG-кадры камеры (нужен Pillow)
```

## Автотесты

Всё одной командой (нужен Python 3.10+ и Godot 4.5.1):

```bash
python3 tools/run_checks.py --godot /путь/к/godot
```

Скрипт сам поднимает эмулятор, запускает игру в `--headless` и печатает отчёт:

```
[OK  ] waiting     1.1 c  игра сама подтвердила ожидание
[OK  ] physics     2.1 c  гол засчитан
[OK  ] protocol    4.7 c  подтверждены 2 игрока, калибровка завершена, READY->PLAY,
                          ракетка следует за головой (Δ=49 px)
[OK  ] leave      10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] swap       10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] stale      10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY → GOAL
[OK  ] drop        4.3 c  игра завершилась сама, код 0
[OK  ] video       8.1 c  состояния: READY → PLAY
```

Отдельные запуски вручную:

```bash
godot --headless --path . -- --selftest=waiting    # ожидание без источника трекинга
godot --headless --path . -- --selftest=physics    # демо-матч: гол засчитывается
godot --headless --path . -- --port=PORT --selftest=protocol   # 2 игрока, калибровка, движение, жесты
godot --headless --path . -- --port=PORT --selftest=log        # печатать смены состояния
godot --path . -- --win-score=3                    # короткий матч до 3 голов
```

## Что проверить (приёмочный чек-лист)

- [ ] Без источника трекинга — экран «Встаньте вдвоём перед камерой», игра не падает.
- [ ] Два игрока в кадре → отсчёт 3-2-1 → матч. Кто левее в кадре — игрок 1.
- [ ] Наклон головы влево/вправо двигает ракетку вверх/вниз; присед/выпрямление — вперёд/назад.
- [ ] Гол в лунку засчитывается, счёт растёт, после 5 голов — «Игрок N победил!».
- [ ] Игрок ушёл из кадра → пауза с причиной; вернулся → отсчёт и продолжение.
- [ ] У игрока сменился `track_id` при том же `slot` → состояние сброшено (новый человек).
- [ ] `players` пуст / данные устарели / соединение закрылось → пауза, затем ожидание или выход.
- [ ] Жесты не влияют на игру: они только подсвечивают кольцо ракетки
      (проверка самого сигнала `gesture`), поэтому низкий `confidence` безопасен.
- [ ] В HUD видно мини-превью камеры с рамками игроков (при `--video`).
- [ ] Клавиши оператора не перехватываются: **Tab** (выход 11), **Esc** (выход 0),
      **N** (выход 10), **Shift+Esc** (выход 12).

## Структура

```

godotar.json           — манифест игры (api 1, tracking: preview)
game/Main.tscn         — корневая сцена
game/Main.gd           — вся логика игры (физика, отрисовка, звук, автотесты)
shared/GameDirector.gd — адаптер трекинга (дословно из GodotAR.md §6, не менять)
shared/VirtualPlayer.gd— модель игрока (дословно из GodotAR.md §6, не менять)
tools/mock_tracker.py  — эмулятор системы трекинга (Python 3.10+)
tools/run_checks.py    — автопроверки всех сценариев одной командой
```

## Замечание по звуку

Звуковые эффекты синтезируются в реальном времени (ретро-«квадратные» волны)
и не требуют аудиофайлов. Если в вашей сборке Godot нет аудиодрайвера,
игра просто работает без звука.

## Что этот тест говорит о формате

- **Трекинг даёт позицию, а не скелет.** Доступны рамка силуэта, лодыжки и три
  жеста (`jump`, `lean_left`, `lean_right`). Для аэрохоккея этого достаточно:
  ракетка живёт в 2D и управляется положением головы (прокси — верхняя точка
  рамки). Хуже будет в играх, где нужны кисти или мелкая моторика.
- **Задержка.** Пакеты идут ~30 раз в секунду, «свежим» игрок считается до
  0,5 с (`age_ticks < 15`). Игра сглаживает вход (`HEAD_RATE`) и интерполирует
  ракетку, поэтому управление ощущается плавно, но с откликом ~0,1–0,2 с.
  Для аркад это нормально, для соревновательных реакций — вряд ли.
- **Идентичность важнее координат.** Основная сложность — не управление, а
  жизненный цикл игрока: `(slot, track_id)`, подтверждение измерениями,
  освобождение слота, возврат человека в кадр. Здесь на это уходит большая
  часть кода (пауза, перекалибровка, приём нового `track_id`).
- **`preview` достаточно.** Игра объявляет `"tracking": "preview"`: нужен
  только JPEG-кадр и рамки. `arena` (индексная маска + фон) понадобится, если
  захочется рисовать эффекты ровно по силуэтам.
- **Ошибки оператора и камеры не должны ломать игру.** Обрыв TCP завершает
  игру (это делает адаптер), потеря игрока — пауза, долгая потеря — возврат на
  экран ожидания. Клавиши оператора (Tab/Esc/N/Shift+Esc) игра не перехватывает.

## Ограничения текущей версии

- Матч до 5 голов, реванш автоматический (через 8 с) или кнопкой в демо-режиме.
- Два игрока только; при трёх и более людях в кадре берутся крайний левый и
  крайний правый.
- Настройки чувствительности (`RANGE_X`, `RANGE_Y`, `DEADZONE`) — константы в
  начале `game/Main.gd`; их стоит подкрутить под конкретную камеру и рост игроков.
- Диапазон калибруется на каждом раунде: если игрок стоит вполоборота, нейтраль
  смещается — это ожидаемо и лечится повторной калибровкой (просто постойте ровно
  в отсчёт).
