# Neon Air Hockey — тестовая motion-игра (Godot AR API v2)

Аэрохоккей на двоих в ретро-неоновом стиле: вид сверху, 2D. Слева в кадре —
игрок 1 (голубая ракетка), справа — игрок 2 (розовая). Цель — забить диск
в лунку соперника. Матч до 5 голов.

Игра написана под **Godot AR API v2** (`docs/GodotAR-v2.md`): поза из
YOLO11s-pose, фазы жестов, состояние трека, метрики задержки. Профиль
`preview` — маленькое превью камеры в HUD; `points` (без видео) включается
одной строкой в `godotar.json`, если важнее отзывчивость.

## Управление

Ввод — **наклон корпуса**, в единицах роста, поэтому близкий и дальний игрок
управляют одинаково. Формула: `lean = (head.x − feet_mid.x) × (W/H) ÷ body_height`.

| Движение | Ракетка |
|---|---|
| наклон влево / вправо | вверх / вниз по столу |
| шаг к камере / от камеры | вперёд / назад |
| прыжок (жест `jump`, фаза `start`) | толчок: ракетка уходит вперёд и бьёт |

- Нейтраль наклона и масштаб (`body_height`) калибруются в отсчёт перед
  раундом — стойте ровно, лицом к камере.
- Жест учитывается только при `confidence ≥ 0.75`; фазы `hold`/`end` приходят
  отдельным сигналом и не дают дребезга.
- Если трекер присылает только рамку (старый источник) — включается фолбэк:
  ракетка едет за смещением корпуса в кадре, а полоса ввода в HUD становится
  белой.
- Если пропала точка головы (`head` пустой) — вход замирает на последнем
  значении; через 2 с игра ставит паузу с причиной «потеряна точка головы».

## Запуск

### С реальной системой трекинга

1. Откройте папку `neon_air_hockey/` в Godot 4.5.1 (один раз — чтобы движок
   сгенерировал `.godot/`).
2. В системе трекинга: **Tab → Игры → Добавить игру → выбрать `godotar.json`**.
3. Игра стартует с аргументами `--port=N` (и при необходимости
   `--rotation-seconds=S`).

### Демо без трекинга

Просто запустите проект в Godot: игрок 1 — **WASD**, игрок 2 — **стрелки**,
**Пробел** — старт матча / реванш.

### Эмулятор трекинга (без камеры)

```bash
python3 tools/mock_tracker.py
```

Скрипт напечатает команду вида `godot --path . -- --port=PORT`. Эмулятор
присылает двух игроков в формате v2 (поза, `body_height`, состояние трека,
фазы жестов, `tentative_players`, `frame_size`) и умеет сценарии:

```bash
python3 tools/mock_tracker.py --leave 12          # правый ушёл на 3 с и вернулся
python3 tools/mock_tracker.py --swap 12           # новый track_id в том же slot
python3 tools/mock_tracker.py --empty 12          # players пуст
python3 tools/mock_tracker.py --stale 12          # поток молчит (данные устаревают)
python3 tools/mock_tracker.py --drop 12           # обрыв соединения
python3 tools/mock_tracker.py --lost 6            # state="lost" при свежих данных
python3 tools/mock_tracker.py --reacquire 6       # потеря трека и возврат (reacquired)
python3 tools/mock_tracker.py --reacq-flag 6      # reacquired=true при confirmed
python3 tools/mock_tracker.py --lose-head 6       # пропала точка головы
python3 tools/mock_tracker.py --legacy            # источник в стиле v1 (без позы)
python3 tools/mock_tracker.py --lowconf           # жесты с confidence 0.45
python3 tools/mock_tracker.py --video             # JPEG-кадры (нужен Pillow)
```

## Автотесты

```bash
python3 tools/run_checks.py --godot /путь/к/godot
```

Скрипт поднимает эмулятор, запускает игру в `--headless` и проверяет 14 сценариев:

```
[OK  ] waiting     1.1 c  игра сама подтвердила ожидание
[OK  ] physics     2.1 c  гол засчитан
[OK  ] protocol    4.7 c  подтверждены 2 игрока, калибровка завершена, READY->PLAY,
                          ракетка следует за головой (Δ=137 px)
[OK  ] leave      10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] swap       10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] stale      10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] drop        4.2 c  игра завершилась сама, код 0
[OK  ] phases      6.1 c  фазы hold/end и толчок видны в логе
[OK  ] lowconf     5.1 c  ложных толчков нет
[OK  ] lost        7.6 c  пауза по state и возврат в игру
[OK  ] reacquire   8.1 c  возврат трека обработан
[OK  ] nohead     10.1 c  «слепой» режим и пауза сработали
[OK  ] legacy      8.1 c  фолбэк по рамке, раунд идёт
[OK  ] video       8.1 c  состояния: READY → PLAY → GOAL → READY
```

Отдельные запуски вручную (полезно при настройке):

```bash
godot --headless --path . -- --selftest=waiting    # ожидание без источника
godot --headless --path . -- --selftest=physics    # гол засчитывается
godot --headless --path . -- --port=PORT --selftest=protocol
godot --headless --path . -- --port=PORT --selftest=log   # STATE/PAUSE/CALIB/INPUT/PHASE
godot --path . -- --no-audio --win-score=3         # без звука, короткий матч
```

В режиме `log` игра печатает `INPUT slot=… lean=… bh=… fallback=…` — по этим
числам удобно подбирать чувствительность.

## Что проверить руками (приёмочный чек-лист)

- [ ] Без источника трекинга — «Встаньте вдвоём перед камерой», игра не падает.
- [ ] Два игрока в кадре → отсчёт 3-2-1 → матч. Кто левее — игрок 1.
- [ ] Наклон влево/вправо двигает ракетку вверх/вниз; шаг к камере — вперёд.
- [ ] Прыжок даёт толчок (ракетка уходит вперёд и бьёт).
- [ ] Полоса ввода в HUD повторяет наклон и белеет, если вход по рамке (фолбэк).
- [ ] Гол засчитывается, счёт растёт, после 5 голов — «Игрок N победил!».
- [ ] Игрок ушёл → пауза с причиной; вернулся → отсчёт и продолжение.
- [ ] `state="lost"` при свежих данных → пауза сразу, не через 0,5 с.
- [ ] Новый `track_id` в том же слоте → состояние стороны сброшено.
- [ ] `players` пуст / поток замолк / соединение закрылось → пауза, ожидание, выход.
- [ ] Жест ниже `confidence 0.75` ничего не делает.
- [ ] Мини-превью камеры с рамками игроков (в профиле `preview`).
- [ ] Клавиши оператора не перехватываются: **Tab** (11), **Esc** (0),
      **N** (10), **Shift+Esc** (12).

## Что этот тест говорит о формате

- **Поза решает проблему управления.** `head` + `feet` + `body_height` дают
  безразмерный ввод: наклон в долях роста не зависит от расстояния до камеры.
  Это то, чего не хватало для «настоящего» управления в v1.
- **`state` важнее возраста.** Игрок с `state="lost"` остаётся в `players()`,
  пока измерение моложе 0,5 с, поэтому пауза должна опираться на `state`,
  а не на `age_ticks`.
- **`frame_size` надо проверять.** Точки нормированы отдельно по ширине и
  высоте, поэтому X нужно умножать на `W/H`; у старого источника поле нулевое —
  в игре есть guard и запасной 16:9.
- **Узкое место — не управление, а жизненный цикл**: `slot`+`track_id`,
  подтверждение, освобождение слота, возврат, `reacquired`. На это уходит
  большая часть кода.
- **`preview` достаточно**, `arena` (маска + фон) аэрохоккею не нужен; для
  отзывчивости есть профиль `points` без видео.
- **Ошибки камеры и оператора не должны ломать игру**: обрыв TCP завершает игру
  (это делает адаптер), потеря игрока — пауза, долгая потеря — экран ожидания.

## Ограничения текущей версии

- Матч до 5 голов; реванш автоматический (через 8 с) или кнопкой в демо-режиме.
- Два игрока; при трёх и более в кадре берутся крайний левый и крайний правый.
- Чувствительность — константы в начале `game/Main.gd`: `RANGE_LEAN` (наклон),
  `RANGE_PROX` (шаг), `DEADZONE`, `PUSH_DIST`. Подбираются по логу `INPUT`.
- Вторая ось (шаг) конфликтует с приседанием: присед тоже меняет `body_height`.
  Если это мешает — ведите одну ось наклоном и толчок прыжком.
- В `--headless` при выходе Godot пишет `ObjectDB instances leaked at exit`
  (`AudioStreamGeneratorPlayback`, аудиодрайвер Dummy). В окне с настоящим
  драйвером этого нет; для чистой проверки можно запускать с `--no-audio`.
