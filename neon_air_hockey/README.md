# Neon Air Hockey — тестовая motion-игра (Godot AR API v2)

Аэрохоккей на двоих в ретро-неоновом стиле: вид сверху, 2D. Слева в кадре —
игрок 1 (голубая ракетка), справа — игрок 2 (розовая). Цель — забить диск
в лунку соперника. Матч до 5 голов.

Игра написана под **Godot AR API v2** (`docs/GodotAR-v2.md`): поза из
YOLO11s-pose, фазы жестов, состояние трека, метрики задержки. Профиль
`preview` — маленькое превью камеры в HUD; `points` (без видео) включается
одной строкой в `godotar.json`, если важнее отзывчивость.

## Управление

Ввод — **лицо как курсор** в своей половине стола: две независимые оси, нейтраль
снимается в отсчёт. Ничего наклонять не нужно — достаточно смотреть в камеру.

| Движение | Ракетка |
|---|---|
| лицо вверх / вниз | вверх / вниз по столу (ось Y) |
| лицо влево / вправо | вперёд / назад по столу (ось X) |
| прыжок (жест `jump`, фаза `start`) | толчок: ракетка уходит вперёд и бьёт |

Три режима, переключаются флагом `--control=` (или клавишами **1 / 2 / 3**,
смена режима перезапускает отсчёт и калибровку):

| `--control=` | Что измеряется | Единицы и ход до края |
|---|---|---|
| `face` (по умолчанию) | положение носа (`keypoints[0]`, иначе середина `head`) | доли высоты кадра: **X 0.14**, **Y 0.08** |
| `tilt` | поворот головы (нос относительно линии глаз) и наклон головы набок (roll глаз) | поворот — в долях межглазного расстояния **0.20**, roll — радианы **0.22** |
| `lean` | прежний вариант: наклон корпуса к камере и шаг к камере | доли роста: **0.18**, **0.22** |

Внутри обе оси приводятся к одному виду: `raw` → `(raw − нейтраль) / range`
→ мёртвая зона 0.10 → `× gain` → `ax, ay` в `−1…1`. По X курсор занимает всю
свою половину стола, по Y — всю высоту.

```bash
godot --path . -- --port=N --control=face      # по умолчанию
godot --path . -- --port=N --control=tilt      # наклон головы набок
godot --path . -- --port=N --control=lean      # старый наклон корпуса
godot --path . -- --port=N --gain=1.5          # чувствительность (0.2…4)
godot --path . -- --port=N --flip-x --flip-y   # инверсия осей
godot --path . -- --port=N --debug             # панель чисел в HUD (или F1)
```

- Нейтраль обеих осей калибруется в отсчёт перед раундом — стойте ровно,
  смотрите в камеру. Перед калибровкой `ax = ay = 0`, ракетка в центре.
- Если в источнике нет позы, но есть рамка (старый источник) — включается
  фолбэк: вход считается по смещению рамки, точка на HUD-квадрате становится
  белой. Если поза была, а нос пропал, — вход держит последнее значение.
- Если пропала точка головы (`head` пустой, а поза есть) — вход замирает;
  через 2 с игра ставит паузу с причиной «потеряна точка головы». Время
  считается и в отсчёт, и после гола, чтобы потеря не «терялась» за голом.
- Жест учитывается только при `confidence ≥ 0.75`; фазы `hold`/`end` приходят
  отдельным сигналом и не дают дребезга.
- В HUD у каждого игрока квадрат ввода: точка = текущее `(ax, ay)`, то есть
  куда ракетка поедет. Размер хода и чувствительность правятся константами
  `RANGE_FACE_X/Y`, `RANGE_TILT_X/Y`, `RANGE_LEAN` в начале `game/Main.gd`.

### Запись и воспроизведение трассы (`packets.jsonl`)

Система трекинга **не отдаёт** файл с пакетами — она шлёт их по TCP. Чтобы
получить `packets.jsonl`, его пишет сама игра:

```bash
godot --path . -- --port=N --record=packets.jsonl     # пишет каждый новый кадр
godot --path . -- --port=N --record                   # путь по умолчанию:
                                                      # user://packets.jsonl
python3 tools/mock_tracker.py --replay packets.jsonl  # проиграть запись обратно
```

В обычном сценарии игру запускает система трекинга, и флаги ей не передать.
На этот случай есть файл-переключатель: создайте `neon_air_hockey/record.cfg`
(пустой — писать в `user://packets.jsonl`, или с путём в первой строке) —
игра начнёт запись при обычном запуске из системы. Полный путь печатается
в консоль игрой: `пишу трассу ввода в /home/…/packets.jsonl`.
Удалите `record.cfg`, чтобы выключить запись.

Формат — по объекту JSON на строку, только по новым `sample_id`:

```json
{"t": 12.34,
 "players": [{"slot": 0, "track_id": 7, "state": "confirmed",
              "color": [0.1, 0.8, 1.0], "rect": [0.21, 0.24, 0.15, 0.53],
              "head": [0.28, 0.23, 0.96], "feet": [[0.23, 0.75], [0.33, 0.75]],
              "feet_confidence": 0.93, "body_height": 0.53,
              "keypoints": [[0.28, 0.23, 0.97], "..."]}],
 "events": [{"slot": 0, "track_id": 7, "action": "jump", "phase": "start",
             "confidence": 0.91}]}
```

Такой файл — готовый вход для разбора «почему ракетка дёргается»: по `head`
и `keypoints` видно, что именно пришло, а реплей даёт воспроизводимый прогон
без камеры.

## Запуск

### С реальной системой трекинга

1. Откройте папку `neon_air_hockey/` в Godot 4.5.1 (один раз — чтобы движок
   сгенерировал `.godot/`).
2. В системе трекинга: **Tab → Игры → Добавить игру → выбрать `godotar.json`**.
3. Игра стартует с аргументами `--port=N` (и при необходимости
   `--rotation-seconds=S`).

### Демо без трекинга

Просто запустите проект в Godot: игрок 1 — **WASD**, игрок 2 — **стрелки**,
**Пробел** — старт матча / реванш, **1 / 2 / 3** — режим ввода, **F1** — панель
чисел в HUD.

### Эмулятор трекинга (без камеры)

```bash
python3 tools/mock_tracker.py
```

Скрипт напечатает команду вида `godot --path . -- --port=PORT`. Эмулятор
присылает двух игроков в формате v2 (поза, `body_height`, состояние трека,
фазы жестов, `tentative_players`, `frame_size`) и умеет сценарии:

```bash
python3 tools/mock_tracker.py --leave 12          # правый ушёл на 3 с и вернулся
python3 tools/mock_tracker.py --swap 12           # новый track_id в том же slot
python3 tools/mock_tracker.py --empty 12          # players пуст
python3 tools/mock_tracker.py --stale 12          # поток молчит (данные устаревают)
python3 tools/mock_tracker.py --drop 12           # обрыв соединения
python3 tools/mock_tracker.py --lost 6            # state="lost" при свежих данных
python3 tools/mock_tracker.py --reacquire 6       # потеря трека и возврат (reacquired)
python3 tools/mock_tracker.py --reacq-flag 6      # reacquired=true при confirmed
python3 tools/mock_tracker.py --lose-head 6       # пропала точка головы
python3 tools/mock_tracker.py --legacy            # источник в стиле v1 (без позы)
python3 tools/mock_tracker.py --lowconf           # жесты с confidence 0.45
python3 tools/mock_tracker.py --video             # JPEG-кадры (нужен Pillow)
python3 tools/mock_tracker.py --replay packets.jsonl   # проиграть запись игры
```

Эмулятор двигает и лицо (нос, глаза, наклон/поворот головы), и силуэт, поэтому
на нём проверяются все три режима ввода; `--speed 2` ускоряет реплей.

## Автотесты

```bash
python3 tools/run_checks.py --godot /путь/к/godot
```

Скрипт поднимает эмулятор, запускает игру в `--headless` и проверяет 15 сценариев:

```
[OK  ] waiting     1.1 c  игра сама подтвердила ожидание
[OK  ] physics     2.1 c  гол засчитан
[OK  ] protocol    4.7 c  подтверждены 2 игрока, калибровка завершена, READY->PLAY,
                          ракетка следует за лицом (Δ=116 px)
[OK  ] control    27.2 c  face 100/49; tilt 100/42; lean 36/100 (обе оси, кадры записаны)
[OK  ] leave      10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] swap       10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] stale      10.1 c  состояния: READY → PLAY → PAUSED → READY → PLAY
[OK  ] drop        4.2 c  игра завершилась сама, код 0
[OK  ] phases      6.1 c  фазы hold/end и толчок видны в логе
[OK  ] lowconf     5.1 c  ложных толчков нет
[OK  ] lost        7.6 c  пауза по state и возврат в игру
[OK  ] reacquire   8.1 c  возврат трека обработан
[OK  ] nohead     10.1 c  «слепой» режим и пауза сработали
[OK  ] legacy      8.1 c  фолбэк по рамке, раунд идёт
[OK  ] video       8.1 c  состояния: READY → PLAY → GOAL → READY
```

Отдельные запуски вручную (полезно при настройке):

```bash
godot --headless --path . -- --selftest=waiting    # ожидание без источника
godot --headless --path . -- --selftest=physics    # гол засчитывается
godot --headless --path . -- --port=PORT --selftest=protocol
godot --headless --path . -- --port=PORT --selftest=log   # STATE/PAUSE/CALIB/INPUT/PHASE
godot --path . -- --no-audio --win-score=3         # без звука, короткий матч
godot --path . -- --port=PORT --record=packets.jsonl   # записать трассу
godot --path . -- --control=tilt --debug           # другой режим + числа в HUD
```

В режиме `log` игра печатает
`INPUT slot=… mode=… raw=(…) neutral=(…) range=(…) ax=… ay=… fallback=… pos=(…)`
— по этим числам удобно подбирать чувствительность: `raw` — что пришло,
`neutral` — что снято в отсчёт, `range` — ход до края.

Проверка `control` гоняет все три режима и требует, чтобы обе оси отклонялись
у обоих игроков и чтобы файл записи наполнялся.

## Что проверить руками (приёмочный чек-лист)

- [ ] Без источника трекинга — «Встаньте вдвоём перед камерой», игра не падает.
- [ ] Два игрока в кадре → отсчёт 3-2-1 → матч. Кто левее — игрок 1.
- [ ] Лицо вверх/вниз — ракетка вверх/вниз; лицо влево/вправо — вперёд/назад.
- [ ] Клавиши **1 / 2 / 3** меняют режим (лицо / наклон головы / корпус), отсчёт
      начинается заново и нейтраль пересчитывается.
- [ ] Прыжок даёт толчок (ракетка уходит вперёд и бьёт).
- [ ] Квадрат ввода в HUD повторяет `(ax, ay)` и белеет, если вход по рамке.
- [ ] `--record=…` создаёт `packets.jsonl`, `--replay` проигрывает его без камеры.
- [ ] Гол засчитывается, счёт растёт, после 5 голов — «Игрок N победил!».
- [ ] Игрок ушёл → пауза с причиной; вернулся → отсчёт и продолжение.
- [ ] `state="lost"` при свежих данных → пауза сразу, не через 0,5 с.
- [ ] Новый `track_id` в том же слоте → состояние стороны сброшено.
- [ ] `players` пуст / поток замолк / соединение закрылось → пауза, ожидание, выход.
- [ ] Жест ниже `confidence 0.75` ничего не делает.
- [ ] Мини-превью камеры с рамками игроков (в профиле `preview`).
- [ ] Клавиши оператора не перехватываются: **Tab** (11), **Esc** (0),
      **N** (10), **Shift+Esc** (12).

## Что этот тест говорит о формате

- **Поза решает проблему управления.** `keypoints` дают нос и глаза: положение
  лица — это абсолютный курсор, его не нужно ничем заменять. `head` + `feet` +
  `body_height` дают безразмерный запасной вариант (наклон в долях роста не
  зависит от расстояния до камеры). Обе схемы живут в игре одновременно.
- **`state` важнее возраста.** Игрок с `state="lost"` остаётся в `players()`,
  пока измерение моложе 0,5 с, поэтому пауза должна опираться на `state`,
  а не на `age_ticks`.
- **`frame_size` надо проверять.** Точки нормированы отдельно по ширине и
  высоте, поэтому X нужно умножать на `W/H`; у старого источника поле нулевое —
  в игре есть guard и запасной 16:9.
- **Узкое место — не управление, а жизненный цикл**: `slot`+`track_id`,
  подтверждение, освобождение слота, возврат, `reacquired`. На это уходит
  большая часть кода.
- **`preview` достаточно**, `arena` (маска + фон) аэрохоккею не нужен; для
  отзывчивости есть профиль `points` без видео.
- **Ошибки камеры и оператора не должны ломать игру**: обрыв TCP завершает игру
  (это делает адаптер), потеря игрока — пауза, долгая потеря — экран ожидания.

## Ограничения текущей версии

- Матч до 5 голов; реванш автоматический (через 8 с) или кнопкой в демо-режиме.
- Два игрока; при трёх и более в кадре берутся крайний левый и крайний правый.
- Чувствительность — константы в начале `game/Main.gd`: `RANGE_FACE_X/Y`
  (лицо), `RANGE_TILT_X/Y` (голова), `RANGE_LEAN`, `RANGE_PROX` (корпус),
  `DEADZONE`, `PUSH_DIST`; плюс флаг `--gain=`. Подбираются по логу `INPUT`.
- В режиме `lean` вторая ось (шаг) конфликтует с приседанием: присед тоже
  меняет `body_height`. В режимах `face` и `tilt` этого конфликта нет.
- В режиме `tilt` нужны все три точки (нос и два глаза) с `z ≥ 0.30` и лицо
  шириной больше 0.006 кадра; если лицо мелкое — режим сам откатывается на
  `face`, поэтому далеко от камеры лучше `face`.
- В `--headless` при выходе Godot пишет `ObjectDB instances leaked at exit`
  (`AudioStreamGeneratorPlayback`, аудиодрайвер Dummy). В окне с настоящим
  драйвером этого нет; для чистой проверки можно запускать с `--no-audio`.

```

game/Main.gd           — вся логика: ввод, физика, отрисовка, звук, автотесты

```
