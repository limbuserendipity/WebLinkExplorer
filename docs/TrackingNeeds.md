# Что игре нужно от трекинга (Godot AR API v2)

Документ для того, кто расширяет интерфейс зеркала. Составлен по опыту
**Neon Air Hockey** (2 игрока, управление головой/корпусом) и по списку
моделей зеркала (YOLO11s-pose, YOLO11s-seg, Hand Landmarker, YOLOE-11s-seg,
Depth Anything V2, SegFormer-b0, DINOv2).

Порядок = приоритет. Всё перечисленное — **дополнительные поля**: старые игры
их игнорируют, `api` в манифесте можно не менять.

---

## 0. Почему сейчас «беда с управлением»

Игра берёт `camera_rect_norm` и считает верхнюю центральную точку рамки «головой».
Четыре причины, почему это ощущается плохо:

| Причина | Что происходит |
|---|---|
| Рамка зависит от рук | поднял руку/сумку — «голова» прыгнула, ракетка дёрнулась |
| Масштаб кадра ≠ масштаб человека | ближний игрок ходит по кадру на 0.20, дальний на 0.07 — чувствительность у всех разная |
| Абсолютная позиция вместо смещения | любой шаг в сторону = рывок ракетки, «нуля» нет |
| Фронтальная камера не видит глубину | ось «вперёд-назад» приходится брать приседом — самый шумный канал |

Всё это лечится тремя полями из YOLO11s-pose, которые в пакет не попадают.

---

## 1. Нужно прямо сейчас (P0) — 3 поля

| Поле | Формат | Зачем |
|---|---|---|
| `head` | `{"p": [x, y], "conf": 0.96}` — середина глаз/носа из 17 точек позы | устойчивая точка головы вместо верха рамки; не зависит от рук |
| `body_height` | число, нормированное (например `feet_y − head_y`) | безразмерная база: гасит разницу в росте и расстоянии |
| `feet` | уже есть (`feet_norm` + `feet_confidence`) | опора для наклона; **не убирать** |

С ними управление становится «джойстиком наклона», и это не эвристика, а физика:

```
lean_x  = (head.x − feet_mid.x) / body_height        # −1…1 — наклон влево/вправо
lean_y  = (feet_mid.y − head.y)  / body_height        # −1…1 — наклон вперёд/назад
depth   = body_height / body_height_at_calibration − 1 # ≈ шаг к камере/от камеры
```

- наклон считается в единицах роста → близкий и дальний игрок чувствуют одинаково;
- лодыжки стоят на полу, поэтому наклон не «съезжает» от шагов;
- `body_height` — готовый прокси расстояния: **модель глубины для этой оси не нужна**.

Хватит двух чисел и одной точки, чтобы игра перестала быть «беда».

## 2. Очень желательно (P1)

| Поле | Формат | Зачем |
|---|---|---|
| `shoulders` | `[[x, y, conf], [x, y, conf]]` | наклон плеч устойчивее головы; ширина плеч — второй масштаб; «руки вверх» без жестов |
| `hips` | `[[x, y, conf], [x, y, conf]]` | центр корпуса, присед, определение «ушёл вбок, но остался в кадре» |
| `conf` на каждую точку | 0…1 | закрытые/срезанные точки игнорировать, а не сглаживать |
| `state` | `"tentative"` \| `"confirmed"` \| `"lost"` + `lost_since` | сейчас игра угадывает по `age_ticks`; явное состояние = меньше пауз «на пустом месте» |
| `reacquired` | `true` при возврате того же `track_id` | отличить «вернулся» от «новый человек в том же слоте» |
| `wrists` | `[[x, y, conf], [x, y, conf]]` | «толчок»/удар рукой без полного трекинга кистей |

## 3. Когда захотим круче (P2)

- **Кисти** (Hand Landmarker): `palm`, `pinch` 0…1, `grab` + позиция — ракетка едет за ладонью, «щелчок» = удар; другое ощущение игры.
- **Маска игрока** (`arena`): неоновое свечение и обводка по силуэту, эффекты «за фигурой».
- **Глубина в метрах у лодыжек** + плоскость пола: поставить виртуальный стол в комнате, а не в кадре; масштаб «как в жизни».
- **Предметы** (YOLOE): реальная ракетка/кружка как контроллер. Нужен стабильный `object_id` (как `track_id` у людей) и события «появился/пропал».
- **Капабилити-хендшейк и подписка**: игра говорит, что ей нужно (`players`, `gestures`, `video`, `hands`), зеркало не шлёт 1280-пиксельные кадры, если просят только точки.

## 4. Предлагаемый формат (обратно совместимый)

```json
{
  "frame_id": 8123,
  "tracking_age": 0.041,
  "frame_age": null,
  "capabilities": ["pose", "hands", "seg", "depth"],
  "players": [
    {
      "slot": 0, "track_id": 42, "state": "confirmed", "reacquired": false,
      "color": [0.1, 0.8, 1.0],
      "rect": [0.21, 0.18, 0.16, 0.55],
      "head": {"p": [0.29, 0.21], "conf": 0.96},
      "shoulders": [[0.24, 0.30, 0.95], [0.34, 0.31, 0.93]],
      "hips": [[0.26, 0.52, 0.88], [0.33, 0.52, 0.90]],
      "feet": [[0.25, 0.72], [0.34, 0.72]],
      "feet_confidence": 0.92,
      "body_height": 0.51,
      "mask_slot": 1, "sample_id": 8123
    }
  ],
  "gestures": [
    {"id": 91, "slot": 0, "track_id": 42, "action": "jump",
     "phase": "start", "confidence": 0.95, "at": 12.418}
  ]
}
```

Правила, которые важно сохранить:

1. любое новое поле **опционально**; игра обязана работать без него (у нас есть фолбэк на рамку);
2. `gestures` получают `phase: start|hold|end` и длительность — «держу руку поднятой» нужно чаще, чем «прыгнул»;
3. `feet` остаётся, даже когда появятся `hips`: на нём держится весь наклон.

## 5. Латентность важнее новых полей

Это отдельная и, возможно, главная просьба.

- Сейчас в одном TCP-потоке идут **и точки, и до 3 JPEG (до 4 МиБ)**. TCP не умеет «пропустить старое»: пока не дойдёт кадр, 30 Гц точек стоят.
  Игра по `age_ticks` это увидит как «потерян сигнал» и поставит паузу — а это не потеря, а очередь.
- Предложение: **разделить потоки**. Пакет состояния (`players` + `gestures`, ~1–2 КБ) — отдельно и всегда свежий («последний побеждает»), изображения — вторым потоком и «если успели».
  Альтернатива без второго сокета: в JSON писать точки всегда, а кадры отправлять не чаще N раз/с и не больше M КБ.
- Добавить `capture_time` (общие монотонные часы для кадра и точек) — клиент сможет интерполировать и предсказывать, а не просто «ждать следующего пакета».
- Цели: **30–60 Гц** для точек, джиттер < 10 мс, задержка «захват → пакет» < 50 мс. В отладочном оверлее — p50/p95.

У нас в игре уже стоит допуск `STALE = 0.5 с`; если появятся тяжёлые кадры, его придётся растягивать, и это лечится только разделением потоков.

## 6. Инструменты, которые сэкономят дни

| Инструмент | Зачем |
|---|---|
| **Запись и воспроизведение пакетов** (`.jsonl` + кадры по требованию) | настраивать управление без камеры и зала; файл = «живой» вход для игры |
| **Синтетические игроки** с параметрами (рост, расстояние, шум, дрожание) | проверять, что игра не ломается и что чувствительность одинаковая |
| **Режим «только точки»** | отладка управления без 10 к/с видео |
| **JSON Schema** пакета в репозитории | ловить расхождения между зеркалом и игрой в CI, а не в зале |

Заготовка уже есть: `neon_air_hockey/tools/mock_tracker.py` повторяет формат
и умеет сценарии (ушёл / новый `track_id` / пустой список / поток замолк / обрыв).
Если дадите запись с реальной камеры — прогоню игру на ней и подберу константы.

## 7. Что нужно «подобным играм вообще»

Не по моделям, а по смыслу — этим закрывается большинство игр из вашего списка.

| Блок | Что отдать игре | Кому критично |
|---|---|---|
| **Поза 17 точек + conf + масштаб** | `head`, `shoulders`, `hips`, `wrists`, `ankles`, `body_height` | почти всем: Crowd Rail Runner, «Пол — лава», «Крыши», Neon Air Hockey |
| **Состояние трека** | `state`, `lost_since`, `reacquired`, «человек вышел из кадра» как событие | всем: без этого игры ставят паузу «на ровном месте» |
| **Идентичность** | стабильный `track_id` при кратком перекрытии, слоты, порядок слева→направо | всем многопользовательским |
| **Кисти** | `palm`, `pinch` 0…1, `grab`, позиция ладони | «Магия», «Светлячки», «Созвездие», «Дёрни за верёвку» |
| **Маски** | индекс маски + быстрый доступ, «только нужные люди» | «Пол — лава», «Обвал платформ», «Невидимки», «Обмен головами», обводка |
| **Предметы** | `object_id`, класс, центр, маска, события появления/пропажи | «Троны», «Портал», «Шарики», «Уборка зала» |
| **Глубина/пол** | плоскость пола, метры у лодыжек, «глубина в точке» (не вся карта) | «Мяч 3D», «Снегопад», «Муравьиная ферма», «Лазерный коридор» |
| **Разметка комнаты** | полигон пола/стен или готовые сегменты | «Новая комната» |
| **Калибровка зоны** | 4 угла игровой зоны + гомография в метры: игра не должна сама разбираться с перспективой | любым играм «на полу» |
| **Жесты как события** | `start/hold/end`, длительность, cooldown, confidence | всем |
| **Единый словарь** | версия списка действий (`jump`, `lean_left`, `lean_right`, `pinch`, `swipe`…) | всем: сейчас словарь задан неформально |

Отдельно про **жесты**: сейчас сигнал только «начало». Для игр нужнее
«держу» (рука поднята — щит поднят) и «отпустил». И важно, чтобы
`confidence` считался одинаково для всех действий, иначе порог в игре
приходится подбирать на каждый жест свой.

## 8. Что сделаю в игре, когда поля появятся

1. замена `rect.top` на `head` + `lean_x/lean_y` по формуле из §1, мёртвая зона и сглаживание остаются;
2. глубина от `body_height` (шаг к камере/от камеры) вместо приседа, плюс «толчок» по `wrists`/`hips`;
3. авто-глубина: ракетка сама подтягивается по дальней оси к диску — играть становится можно одной осью;
4. индикатор качества ввода (средний `conf` точек в HUD) — сразу видно, когда трекер «плывёт»;
5. неоновая обводка игроков по маске (`arena`), если включим этот режим.

Фолбэк на текущих данных тоже есть: наклон уже можно считать как
`(rect_top_center − feet_mid) / body_height`, где `body_height = feet_y − rect_top`. Это
первый шаг, который не требует правок зеркала.
