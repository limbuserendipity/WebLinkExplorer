# Отзыв на Godot AR API v2

Документ: `docs/GodotAR-v2.md`. Проверено на практике: новые `shared/*.gd`
скопированы дословно в отдельный проект и прогнаны на Godot 4.5.1 (headless)
с двумя синтетическими источниками — «v2-полный» (head, keypoints, state,
gesture_phases, tentative, stats) и «старый v1-совместимый» (как в §5).

## Что закрыто из запроса игры

| Просили | Что есть в v2 | Оценка |
|---|---|---|
| точка головы вместо верха рамки | `head` (`p`, `conf`), пустой словарь если нет | закрыто |
| безразмерная база для наклона | `body_height` в долях высоты кадра | закрыто |
| опора на ноги | `feet` (осталось) + `ankles` | закрыто |
| плечи/бёдра/запястья | `shoulders`, `hips`, `wrists`, `keypoints` (COCO-17) с `conf` | закрыто |
| явное состояние трека | `state` (`confirmed`/`lost`), `lost_since` | закрыто |
| возврат человека | `reacquired`, `reacquired_sample_id` | закрыто |
| жесты как события | `gesture_phase(slot, track_id, action, phase, confidence, at, duration)`, `start/hold/end` | закрыто |
| метрики качества | `tracking_stats()` → `latency_ms`, `jitter_ms`, p50/p95 | закрыто |
| «вас пока не подтвердили» | `tentative_players()` | закрыто |
| единицы кадра | `frame_size`, `capture_time`, `tracking_time` | закрыто |
| не тащить видео ради управления | профиль `points`, кап 384 КиБ на картинку с сохранением точек | закрыто |
| запись/воспроизведение | `packets.jsonl`, `GODOT_AR_RECORD`, `tracker_replay.py`, схема пакета | закрыто |

Проверено, что всё это реально доезжает: `head=(0.307, 0.2) conf=0.97`,
`body_height=0.53`, `keypoints` 16 точек + один `null`, `hips` с `null`,
`state confirmed → lost (lost_since=4.5) → confirmed`, `reacquired sample_id=170`,
`gesture_phase` `start → 11×hold → end`, `tentative_players` с рамкой,
`stats latency p50=41 мс / jitter p50=1.2 мс`, `frame_size=(640, 360)`.

## Найденные ловушки (для документа и для игр)

1. **`frame_size` может быть `(0, 0)`.** Пример источника в §5 этого документа
   не отправляет `frame_size`, и тогда рекомендованная формула наклона
   (`Δx × W/H ÷ body_height`) даёт деление на ноль. У нас проверено: старый
   источник → `frame_size=(0,0)`, `capabilities=[]`, `stats` — пустые словари,
   ошибок нет, но формула без guard ломается. Просить игру проверять
   `frame_size.y > 0` и брать запасное значение (например 16:9) — или слать
   его всегда, даже в старом примере.
2. **`players()` не фильтрует по `state`.** Игрок со `state = "lost"` остаётся
   в `players()`, пока его последнее измерение моложе 0,5 с. Игра, которая
   доверяет только `players()`, считает потерянного игрока свежим. Это стоит
   написать прямым текстом: «если `state != "confirmed"` — данные человека не
   использовать, независимо от возраста».
3. **Аспект кадра.** Формула верна только при `body_height` в долях высоты
   кадра: `lean = (head.x − feet_mid.x) × (W / H) / body_height`. В тексте это
   сказано словами; готовая строка GDScript в примере сэкономила бы ошибки.
4. **`body_height` — не «длина тела», а вертикальная проекция** (так и написано),
   и присед меняет её так же, как шаг к камере. Вторая ось на ней остаётся
   неоднозначной. Мы, скорее всего, оставим одну ось + «толчок» по
   `gesture_phase(jump, hold)`, а вторую сделаем опциональной.
5. **`wrists`/`shoulders`/`hips` — «левая и правая стороны тела участника».**
   Не указано, анатомическая это сторона или сторона изображения (для жестов
   явно сказано «относительно изображения»). Для игр «подними левую руку» это
   критично: просится поле `mirrored` или явная фраза в таблице.
6. **Слот-освобождение для `points` не указано.** В документе есть 0,5 с для
   `preview` и 2 с для `arena`. Для `points` ожидаем 0,5 с — лучше зафиксировать.
7. **Остаточный риск блокировки в профилях с видео.** «Видео и состояние идут
   по одному TCP-соединению» — значит кадр 300–380 КиБ всё ещё задерживает
   точки. Кап 384 КиБ помогает, но head-of-line не исчезает. Полезно добавить
   в `tracking_stats` метрику `queue_ms` (сколько данные ждали отправки) —
   сейчас `latency_ms` измеряет захват → отправку и очередь не видит.
8. **Нет счётчика пакетов состояния.** `frame_id` относится к видео; чтобы
   замечать пропуски в потоке точек, пригодился бы `sample_seq` рядом с
   `sample_id`.
9. **`gesture_phase` может прийти без `start`** (подписались позже, или `end`
   доставляется всегда). Стоит предупредить прямо: `end` без `start` — норма,
   не считать его завершением чужого жеста.
10. **Манифест не позволяет объявить потребности.** `api: 1` общий, а понять,
    умеет ли источник `pose`, можно только по `capabilities` первого пакета,
    то есть уже после запуска. Необязательное поле в `godotar.json`
    (`"needs": ["pose"]`) дало бы хабу шанс предупредить оператора заранее.

## План миграции игры (после подтверждения)

1. `shared/` → новые адаптеры из §6 дословно; `godotar.json` — оставить
   `preview` (превью камеры полезно игрокам) или переключить на `points`,
   если важнее отзывчивость; `arena` для аэрохоккея не нужен.
2. Управление: `lean_x = (head.x − feet_mid.x) × (W/H) / body_height` с
   мёртвой зоной и сглаживанием; нейтраль — за время отсчёта (как сейчас);
   при пустом `head` — фолбэк на `rect.top`; при `state != "confirmed"` —
   пауза сразу, без ожидания 0,5 с.
3. `gesture_phase`: `jump` + `hold` → «толчок» с нарастающей силой, `end` →
   сброс. Это даёт вторую ось, не полагаясь на присед.
4. Вторая (глубинная) ось — опционально, от `body_height / body_height_neutral`.
5. HUD: `tracking_stats()` (p95 задержки, джиттер) + `tentative_players()` как
   подсказка «вас ещё не подтвердили» + индикатор среднего `conf`.
6. Тесты: обновить `tools/mock_tracker.py` до v2 (head, keypoints, state,
   gesture_phases, tentative, frame_size) и добавить проверки: `hold/end`,
   `lost/reacquired`, «источник без `frame_size`», «head исчез»,
   «`state=lost`, но измерение свежее».
